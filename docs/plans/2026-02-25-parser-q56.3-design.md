# Parser q56.3 Design (Expanded Scope)

## Goal

Implement parser baseline (`krueger-q56.3`) with a practical slice that goes beyond tokenizer-only behavior:

- module header + exposing clause
- imports
- type alias declarations
- simple union type declarations
- function declarations with minimal body capture
- parser diagnostics and basic recovery
- doc comment attachment behavior per contract

This pass must satisfy parser BDD scenarios and establish stable parser contracts for q56.4/q56.5.

## Scope

### In scope

1. Public parser entrypoints:
   - `parse_module(source, scanner) -> ParseResult`
   - `parse_tokens(tokens) -> ParseResult`
2. Minimal AST model needed by parser scenarios:
   - module name
   - imports
   - declarations (function/type alias/union)
   - declaration metadata with optional attached doc comment
3. Minimal CST model (parser-owned for now):
   - declaration list with spans and trivia/comment preservation hooks
4. Diagnostics for parse failures with parser-specific codes.
5. Partial recovery: continue parsing later declarations after recoverable errors.

### Out of scope (deferred)

1. Full expression grammar and precedence.
2. Complete, final AST/CST model (q56.4/q56.5 own shape finalization).
3. Visitor integration.

## Architecture

Parser is added as a dedicated package under `src/parser/`, imported by root package.

### Layering

1. `parser/types.mbt`
   - parse result structs
   - parser-owned AST/CST placeholder types
2. `parser/lib.mbt`
   - parser API entrypoints
   - token cursor, parse routines, diagnostics/recovery
3. Root `src/lib.mbt`
   - re-export parser types/functions
   - convenience parse function using default scanner

This keeps parser isolated while allowing root-level API ergonomics.

## Parsing Strategy

### Input path

1. `parse_module(source, scanner)`:
   - call scanner
   - on scan error: return `ParseResult` with scanner diagnostics and no AST/CST
   - on success: delegate to `parse_tokens`
2. `parse_tokens(tokens)`:
   - parse module header
   - parse zero or more imports
   - parse zero or more declarations
   - accumulate diagnostics and partial nodes

### Grammar slice

1. Module header:
   - `module` `Identifier` `exposing` `(` exposing-list `)`
2. Import:
   - `import` `Identifier` (`exposing` `(` exposing-list `)`)?
3. Type alias:
   - `type` `alias` `Identifier` ... `=` ... (captured minimally)
4. Union type:
   - `type` `Identifier` ... `=` ... (captured minimally)
5. Function declaration:
   - `Identifier` args... `=` expression-tail (captured as token slice)

### Recovery

On recoverable parse error:

1. emit parser diagnostic (`KR-PARSE-*`)
2. advance until likely declaration boundary token:
   - `Keyword(Module|Import|Type)` or `Identifier` at top-level
3. continue parsing next declaration/import

No panic/abort for malformed tokens; parser always returns a `ParseResult`.

## Doc Comment Attachment

Doc comments come from `trivia_before` of a declaration-start token.

Attachment rules:

1. find the last doc comment in `trivia_before`
2. if any regular comment appears after that doc comment and before declaration start, do not attach
3. whitespace/newline between doc comment and declaration is allowed
4. if attached, store `DocComment { text, span }` in declaration metadata

This matches the design contract and parser feature scenarios.

## Diagnostics

Parser diagnostics are additive with scanner diagnostics.

Initial parser codes:

- `KR-PARSE-001` expected module header token sequence
- `KR-PARSE-002` malformed import declaration
- `KR-PARSE-003` malformed type declaration
- `KR-PARSE-004` malformed function declaration

All diagnostics include stable spans derived from current token (or nearest previous token when EOF-like).

## Risks and Mitigations

1. **AST/CST churn before q56.4/q56.5**
   - Keep parser model minimal and clearly marked as provisional contracts.
2. **Ambiguous declaration starts**
   - Use conservative recovery markers and diagnostics instead of aggressive inference.
3. **Doc comment edge cases**
   - Codify rules with explicit tests from parser feature and focused whitebox tests.
