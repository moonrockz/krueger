# AST q56.4 Design

## Scope

Implement `krueger-q56.4` by introducing a dedicated `src/ast` package and migrating parser AST ownership to it.

This phase is **AST-only**. CST extraction remains deferred to `krueger-q56.5`.

## Goals

1. Eliminate parser-owned AST type definitions.
2. Introduce domain-rich AST name and path types to avoid primitive obsession.
3. Add expression and type expression nodes with incremental parser migration support.
4. Preserve existing parser behavior and diagnostics while changing AST representation.

## Non-goals

1. Full semantic parsing for all Elm expressions/types.
2. CST package extraction.
3. Visitor implementation.

## Architecture

- New package: `src/ast`
- Parser package imports and emits `@ast` structures.
- Root package re-exports AST types from `@ast`.
- Parser keeps CST and parse result wiring; only AST ownership changes.

## AST Modeling Decisions

### Domain types (avoid primitive obsession)

Use structured name wrappers instead of raw `String` in declarations and references.

- `Identifier`
- `ModuleName`
- `ValueName`
- `TypeName`
- `TypeVarName`
- `ConstructorName`
- `OperatorName`

### Module model

- `ModuleAst`
  - `module_name : ModuleName?`
  - `exposing : Array[ExposedName]`
  - `imports : Array[ImportDecl]`
  - `declarations : Array[Declaration]`
  - `span : Span?`

### Declarations and metadata

- `DocComment`
- `DeclMeta`
- `Declaration`
  - `FunctionDecl`
  - `TypeAliasDecl`
  - `UnionTypeDecl`

### Hybrid expression/type model

Literal payloads remain primitive for now (approved constraint).

- `Expr`
  - `Var(ValueName)`
  - `IntLiteral(Int)`
  - `BinaryOp(Expr, OperatorName, Expr)`
  - `Unparsed(UnparsedExpr)`
- `TypeExpr`
  - `TypeRef(TypeName)`
  - `TypeVar(TypeVarName)`
  - `TypeApp(TypeName, Array[TypeExpr])`
  - `Unparsed(UnparsedTypeExpr)`

Dedicated wrappers for fallback payloads:

- `UnparsedExpr { tokens : Array[Token] }`
- `UnparsedTypeExpr { tokens : Array[Token] }`

### Import/exposing model

- `ImportDecl { module_name : ModuleName, exposing : Array[ExposedName]?, span : Span }`
- `ExposedName` starts with `Value(ValueName)` for current parser coverage.

## Parser migration strategy

1. Keep parse recovery and diagnostics unchanged.
2. Convert parser-produced names to typed wrappers.
3. Migrate function/type alias bodies to hybrid AST fallback nodes (`Unparsed*`).
4. Keep union parsing behavior compatible with current token-driven subset.

## Testing strategy

1. Add AST package tests for wrapper/domain/expr/type constructors.
2. Update parser tests to assert typed AST wrappers and hybrid body nodes.
3. Keep existing behavior tests for diagnostics/recovery/doc-comment attachment.
4. Update root tests and re-export checks.

## Success criteria

1. `src/ast` exists and owns AST contracts.
2. Parser returns `@ast.ModuleAst` in `ParseResult`.
3. All tests pass with updated typed AST assertions.
4. No CST extraction performed in this task.
